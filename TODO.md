  -8%, scalar hit -29%, dead chain 4.2x, `is_missing` 2.8x.
- C extension, phase 1 DONE — `mo_dots/_speedups.c` implements `is_null`,
  `is_not_null`, `is_missing`, `to_data`, `from_data`, `dict_to_data`,

  x86_64/aarch64, macos x86_64 (macos-13) + arm64 (macos-14), windows — no local Mac

  renders them into the autogenerated setup.py (`MO_DOTS_NO_EXTENSIONS` drops
  them for the pure wheel). Measured vs pure: `to_data` 3.3x, `is_missing` 2x,
  attr hit -20%.
- C extension, phase 2 DONE — C base types in `_speedups.c`: `_StoreBase` (single
  slot, shared by `Data` and `FlatList` so the `__class__` reassignment in
  `Data.__setitem__` "." keeps compatible layouts), `_DataBase` (C `tp_getattro`
  with manual MRO walk — no hidden AttributeError raise/catch — plus
  `tp_setattro`, `mp_subscript` fast path, `nb_bool`), `_NullBase` (~20 C slots).
  The Python classes are rebuilt over the C bases via `utils._rebuild_class`
  (class-dict copy minus the C-covered dunders); the pure methods remain as slow
  paths for dotted paths / non-dict slots. Measured vs pure: attr hit 4.6x
  (7.3x vs pre-optimization; ~4.6x plain dict), miss chain 14x, scalar hit 3.4x,
  `Null == 5` 2x. Known trade-offs: `iter(Null)` is a tuple-iterator (was
  list-iterator); default pickling of C-backed instances is unsupported (was
  slot-based; nothing in the repo pickles them).
- C extension, phase 3 DONE — dotted-path `w['a.b.c']` walk in C (bails to pure

  `w['a.b.c']` 1,805→107ns (~19x vs pure; ~2.2x plain dict) — the dotted form
  is now FASTER than `w.a.b.c` attribute chaining (~257ns), which materializes
  intermediate Data wrappers.
- C extension, phase 4 DONE — FlatList column extract in C: `_ListBase`
